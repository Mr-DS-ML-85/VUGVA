Architecture Deep Dive

VUGVA implements a CPU-bypass hybrid memory architecture for GPU virtualization. The CPU only touches 72 bytes of metadata per operation — the actual megabyte-scale data moves via DMA.
DOI: 10.5281/zenodo.21549808

The Core Problem

In multi-GPU clusters without NVLink, tensor data is fragmented across GPU VRAM cards. Moving data between GPUs requires CPU involvement, creating a bottleneck. Traditional approaches copy tensors through CPU memory, wasting bandwidth.

CPU-Bypass Architecture

VUGVA separates control plane (CPU) from data plane (DMA):

Control Plane — 72 Bytes Total

  • 8 bytes — Page table lookup (virtual address → physical location)
  • 64 bytes — DMA descriptor (source, destination, size, flags)

The CPU writes these 72 bytes and returns. It never touches the actual tensor data.

Data Plane — Megabytes via DMA

The DMA engine reads the 64-byte descriptor and transfers the full tensor autonomously. GPU MMU handles address translation. The CPU is free to do other work.

Three-Tier Hierarchy

TierLatencyBandwidthRole
VRAM< 100 ns1,008 GB/sActive tensors (hot)

100x bandwidth gaps between tiers. Background sweeper demotes idle pages. Predictive prefetch promotes K steps ahead.

DMA Descriptor Ring

1,024-slot circular buffer. Each slot is exactly 64 bytes:

// 64-byte DMA descriptor (Paper §3.3)
struct DmaDescriptor {
    src_addr:    u64,  // 8 bytes — source GPU/DRAM address
    dst_addr:    u64,  // 8 bytes — destination address
    size:        u64,  // 8 bytes — transfer size in bytes
    flags:       u64,  // 8 bytes — direction, priority, sync
    metadata:    [u8; 32], // 32 bytes — page table, NUMA hint
}
// Total: exactly 64 bytes. CPU writes this, DMA moves data.

Look-Ahead Prefetch (Algorithm 3)

The prefetch engine reads the attention pattern from the model graph to predict which layers will be needed K steps ahead:

  • K — lookahead depth (configurable, default 2-4 layers)
  • Predicts next K layers from transformer attention heads
  • Issues P2P DMA prefetch while GPU computes current layer
  • Hides PCIe latency completely — data arrives before it's needed
The prefetch gain is >10% on RTX 4060. On systems with higher PCIe latency, gains increase further.

Zero-Dependency Design

VUGVA uses dlopen(3) to load CUDA symbols at runtime:

// No #include, no nvcc, no CUDA toolkit needed
// Just the driver library libcuda.so

unsafe {
    let handle = dlopen(b"libcuda.so\0".as_ptr(), RTLD_NOW);
    let cuInit = dlsym(handle, b"cuInit\0".as_ptr());
    let cuMemAlloc = dlsym(handle, b"cuMemAlloc_v2\0".as_ptr());
    // ... all symbols loaded dynamically
}

This means VUGVA works with any CUDA version (10, 11, 12, 13) without recompilation.
